# Нейронні мережі й моделі: що робить кожна

У системі три моделі, кожна відповідає на своє питання. Разом вони утворюють ланцюг
«побачити → пояснити → виправити», який працює в реальному часі, на кожному кроці 5 мс, лише з
100 вимірюваних каналів (як на заліку toksym).

```
100 приладів ──► v8 ──────────► «чи буде зрив найближчим часом?»          (тривога, p)
            │
            ├──► ImpactNet ───► «наскільки небезпечно і через що?»          (λ, частки 5 механізмів)
            │         │
            │         ▼
            └──► учень fixer ─► «що змінити, щоб зриву не було?»           (дія: одна з 8)
                                         │
                                         ▼
                             fixer змінює уставки → плазма працює далі
```

Моделі лежать поза репозиторієм, у `../models/`. Формат кожної — звичайна здача toksym
(`toksym.json` + `model.py` + ваги).

---

## 1. v8 — модель тривоги («чи буде зрив?»)

| | |
|---|---|
| тека | `../models/submission_v8` |
| тип | градієнтний бустинг (дві голови HistGradientBoosting, дерева експортовано в numpy) |
| вхід | 100 каналів → онлайн-ознаки (`features.py`): f_GW за хордами інтерферометра, q ∝ B_t/I_p, β за діамагнітною петлею, P_rad/P_in, Dα і частота ELM, Mirnov, сідлова петля (locked mode), тренди й EMA 50 мс / 250 мс / 1 с, фаза розряду, сценарій з meta |
| голова A | горизонт 0,1 с — **передвісник**: ловить locked mode, Mirnov, просідання T_e; 94 ознаки |
| голова B | горизонт 4,5 с — **близькість до меж**: f_GW, q, β, P_rad/P_in, Dα; 109 ознак; вага ×0,5 |
| вихід | p = 1 − (1 − A)(1 − 0,5·B) → EMA → **бігучий максимум**; на спаді струму p = 0 |
| роль | тривога для заліку (Test run, toksym): найраніший момент, коли p перевищує поріг |

**Результат** (toksym, seed 1, 40 розрядів, lead 30 мс, бюджет 5 %): 18 з 18 зривів спіймано вчасно,
хибних тривог 1 з 20 (5 %), медіанне випередження 0,77 с.

**Обмеження:** бігучий максимум корисний для тривоги (вона не «гасне»), але для керування потрібне
миттєве значення — його дає `p_now` (EMA без максимуму). Більшу частину зривів v8 ловить за
передвісником, тобто менше ніж за 0,1 с до гасіння: для керування це запізно, тому fixer
спирається ще й на ImpactNet.

## 2. ImpactNet — ризик і причина («наскільки небезпечно і через що?»)

| | |
|---|---|
| тека | `../models/impactnet` (опис — її `README.md`) |
| тип | нейромережа: MLP → 4 причинні згорткові блоки (бачать 155 мс) → GRU (пам'ять до ~1 с) → 5 нейронів |
| вхід | 100 каналів + маски відмов + 18 фізичних величин (`drivers.py`): f_GW, q95 з форми, βN, P_rad/P_in, W, dW/dt, τ_E, H98, запас до порогу L–H тощо |
| вихід | **λ** — інтенсивність зриву, 1/с; ризик кожного механізму; **частки** 5 механізмів (сума 100 %): Грінвальд, q95 (кінк), радіація, Тройон, інші |
| фізичне априорі | кожен нейрон прив'язаний до свого драйвера (f_GW, 2,2/q95, P_rad/P_in, βN/2,8) з порогами формули симулятора; мережа вчить лише поправки на шум і затримки приладів |
| роль | показує **причину** (панель «Залік» — блок «Чинники зриву»; панель «Керування» — «Чинники зриву зараз») і дає **ранній сигнал**: λ росте ще до жереба зриву, коли v8 мовчить |

**Результат** (її тест, 200 розрядів): R² λ = 0,996; головний механізм при λ > 0,1 — 100 %;
механізм у момент зриву — 49 з 49. У нашому заліку (30 розрядів) головний механізм вгадано в 5 з 6 зривів.

**Обмеження:** як будильник слабка (λ стрибає пізно, кидок кубика непередбачуваний), тому тривогу
дає v8. Частки при малій λ (< 0,02) — шум. Тройон у даних майже не спрацьовує.

## 3. Учень fixer — дія («що змінити?»)

| | |
|---|---|
| тека | `../models/fixer_student` (опис — [FIXER.md](FIXER.md), розд. 5а) |
| тип | 16 регресорів HistGradientBoosting (scikit-learn) |
| вхід | 56 ознак (`features.py`): виходи ImpactNet (λ, ризики, частки, f_GW, q95, P_rad/P_in, βN), поточні множники fixer, 16 сирих каналів, фаза розряду, тренди за 0,25 с і 1 с |
| вихід | для кожної з 8 дій — **імовірність зриву за 1 с** після дії і **втрата продуктивності**; обирається дія з найменшою ціною P + α·втрата |
| дії | нічого; густина й D₂ −10 / −20 %; вимкнути неон; Iₚ −10 %; нагрів ±20 %; повернути уставки |
| як навчено | імітація **вчителя-оракула**: копії рушія прораховують усі 8 дій на 1 с уперед і бачать справжню λ; учень вчиться передбачати їхні оцінки **лише з приладів**; плюс розмітка небезпечних станів без керування і один раунд DAgger |
| роль | обирає корекцію для fixer у реальному часі |

**Результат** (100 нових розрядів, seed 2000, ті самі розряди в усіх режимах):

| режим | зриви, яким можна запобігти | W, МДж |
|---|---|---|
| без керування | 31 | 2,371 |
| простий порадник (правила) | 21 | 2,376 |
| вчитель-оракул (бачить прихований стан) | 5 | 2,359 |
| **учень (лише прилади)** | **5** | **2,374** |

Учень зрівнявся з ідеальним двійником без втрати продуктивності (McNemar проти «без керування»:
врятовано 26, зіпсовано 0, p = 3·10⁻⁸).

## 4. Збірки (здачі) і де що використовується

| тека | v8 | ImpactNet | учень | що дає |
|---|---|---|---|---|
| `submission_v8` | ✓ | | | лише тривога p |
| `impactnet` | | ✓ | | λ, причини; p = 1 − e^(−λ·1 с) |
| `v8_impact` | ✓ | ✓ | | тривога + причини |
| `fixer_student` | | ✓ | ✓ | причини + дія (тривога від ImpactNet) |
| **`v8_fixer`** | ✓ | ✓ | ✓ | **повний ланцюг: тривога, причини, дія** |

| де | яка модель | навіщо |
|---|---|---|
| панель **«Керування»** (демонстрація) | `v8_fixer` (за замовчуванням) | прогноз, причини, fixer у реальному часі; сигнал для fixer — більше з миттєвого p v8 і 1 − e^(−λ·1 с) ImpactNet |
| панель **«Залік»** | будь-яка тривожна (`submission_v8`, `v8_impact`, `v8_fixer`…) | оцінка тривоги за правилами toksym; моделі з причинами додають блок «Чинники зриву»; **fixer тут не діє** |
| панель **«Датасет»** | жодна | збір даних |
| `fusionsim teach --mode student` | `fixer_student` або `v8_fixer` | пакетна перевірка керування на фіксованих seed |

Моделі з учнем потребують scikit-learn: сервер запускається з
`OMP_NUM_THREADS=1 ./target/release/fusionsim serve --models-dir ../models --python ../fusion_work/venv/bin/python`.

## 5. На яких режимах моделі перевірені

| режим | стан |
|---|---|
| JET, H-mode-родина, DD (як у toksym) | ✅ на цих розрядах навчено й перевірено всі три моделі |
| JET, сценарій Density limit, DD | ✅ перевірено в браузері: fixer відвертає зрив Грінвальда |
| JET, L-mode, DD | ⚠ не перевірено: малий струм і без нагріву, ризик майже завжди низький |
| JET, DT | ⚠ не перевірено: моделі не бачили DT (інше утримання, α-нагрів) — якість невідома |
| DIII-D, ITER, CENTAUR | ✖ не підходять: 100 каналів відкалібровані під JET |

Також: моделі вчилися на нашому симуляторі **без шуму** (v8 і ImpactNet — на шумних даних
toksym). Учня на шумних даних toksym окремо не перевіряли.

## 6. Протокол: як моделі говорять з симулятором

Звичайна здача toksym: `predict(t, channels)` → число p. У fusionsim сервер у привітанні шле
`"rich": true` (обгортка ставить `model.rich_answers = True`), і модель може повернути словник:

| поле | хто дає | значення |
|---|---|---|
| `p` | усі | тривога для заліку |
| `p_now` | v8_impact, v8_fixer, impactnet, fixer_student | миттєвий сигнал для керування |
| `risk_total`, `share_pct`, `risk` | ImpactNet | λ, частки й ризики механізмів |
| `action`, `costs` | учень | обрана дія fixer і ціна кожної з 8 дій |

Поточні множники fixer модель отримує в `model.extra["scales"]`. Під toksym цього немає: моделі
повертають лише p і лишаються сумісними з заліком організаторів.
