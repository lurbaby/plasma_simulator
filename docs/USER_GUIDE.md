# Інструкція користувача: симулятор, датасет, залік, керування

Ця інструкція — для тих, хто вперше відкриває симулятор. Фізика параметрів і механізмів зриву —
окремо, у [PHYSICS_CONTROLS.md](PHYSICS_CONTROLS.md). Технічні деталі реалізації — у
[../HACKATHON.md](../HACKATHON.md), інтерфейс рушія для скриптів — у [../SIM_API.md](../SIM_API.md).

---

## 1. Запуск

```bash
cd ~/PlasmaHcktn/fusion-sim
export PATH=$HOME/.cargo/bin:$PATH          # у fish: fish_add_path ~/.cargo/bin
./build.sh                                  # один раз після змін у коді (WASM + сервер + інтерфейс)
./target/release/fusionsim serve --models-dir ../models --python ../participant/venv/bin/python
```

Відкрийте **http://127.0.0.1:9999/** → JET → H-mode → Run (або одразу http://127.0.0.1:9999/run/jet).

| ключ | що задає | за замовчуванням |
|---|---|---|
| `--port` | порт | 9999 |
| `--models-dir` | тека, де лежать здачі моделей (кожна — підтека з `toksym.json`) | `./models` |
| `--python` | інтерпретатор для моделей (той, де стоїть numpy) | `python3` |
| `--out` | куди писати датасети й дані заліку | `./fusionsim-data` |

Відносні шляхи можна давати сміливо — сервер перетворює їх на абсолютні.
Якщо сторінка не відкривається — перевірте, чи сервер ще працює і чи не зайнятий порт іншим
процесом (`ss -ltnp | grep 9999`); два сервери на одному порту не стартують.

## 2. Екран симуляції (control room)

- **Угорі ліворуч**: установка (для хакатону — **JET**), сценарій (H-mode / L-mode / Density limit),
  паливо DD/DT. Моделі вчилися на JET + DD.
- **Угорі по центру**: Start / Pause / Reset, швидкість відтворення, ✎ Edit — редактор програми розряду.
- **Угорі праворуч** — три кнопки хакатону:

| кнопка | що робить |
|---|---|
| 🎛 **Керування** | бічна панель: прогноз зриву, причини, порадник, автокерування, ручні уставки |
| ⛁ **Датасет** | зібрати навчальні дані: `measured.csv` (100 каналів) і `shots.csv` (мітки) |
| ⏱ **Залік** | прогнати модель на свіжих розрядах і отримати звіт як у toksym + причини зриву |

Решта екрана — рівновага, часові графіки, параметри плазми, профілі, 3D-вигляд камери.

## 3. ⛁ Датасет

1. **Розрядів** — скільки розрядів зібрати; **Master seed** — число, з якого вони розігруються
   (той самий seed → ті самі розряди); **Записувати кожні** — 5 мс = кожен крок, 20 мс = кожен 4-й.
2. **Колонки файлу** — 100 каналів пишуться завжди (саме їх модель бачить на заліку). Галочки
   додають справжній стан плазми для навчання/аналізу: уставки програми, транспорт, педестал,
   домішки, рівновагу, профілі, а також (наше) **Запаси стійкості** (q95, βN, f_GW, P_rad/P_in) і
   **Інтенсивність зриву λ** (λ та rᵢ — правдиві мітки для мереж на кшталт ImpactNet).
3. **▶ Згенерувати** → прогрес → **↓ measured.csv** і **↓ shots.csv**.

`shots.csv`: `shot_id, seed, master_seed, scenario, duration_s, disrupted, t_trigger_s, t_tq_s,
spontaneous, wall_contact, n_steps, t_end_s`. Запис зривного розряду закінчується **до** термічного
гасіння, як у toksym.

## 4. ⏱ Залік моделі

1. **Модель** — оберіть зі списку (це підтеки `--models-dir`) або перетягніть теку здачі в
   пунктирну рамку. Під списком видно точку входу, файли, нотатку; червоним — що не так
   (немає `toksym.json`, файлу, бібліотеки). «готово до запуску» — можна стартувати.
2. **Випередження (lead), с** — наскільки завчасно до гасіння має бути тривога;
   **Бюджет хибних тривог** — яку частку тихих розрядів можна «злякати» (0.05 = 5 %);
   **Розрядів**, **Seed** — на чому проганяти (200 / 1 — як у toksym; для швидкої перевірки 20–40).
3. **▶ Запустити модель**. Один розряд з моделлю — ~3 с, 200 розрядів — ~10 хв.

### Що в звіті
- **Чотири плитки** (як у toksym): **Спіймано** — частка зривів з тривогою ≥ lead до гасіння;
  **Хибні тривоги** — частка тихих розрядів з тривогою; **Поріг** — підібраний поріг p (найбільше
  спійманих при хибних ≤ бюджету); **Медіанне випередження** — медіана часу тривога → гасіння.
- **Рядок під плитками** — абсолютні числа, кількість спонтанних (виключених) зривів, швидкість моделі.
- **Чинники зриву** (якщо модель віддає частки механізмів, напр. `impactnet`, `v8_impact`):
  - «головний механізм вгадано в N / M зривах»;
  - таблиця по механізмах: середня частка насправді / за моделлю і скільки зривів кожного типу
    вгадано (наведіть мишу — побачите, що модель назвала замість);
  - два кольорові стовпчики — середній розклад насправді і за моделлю.
  «Насправді» — розклад λ самого рушія в момент жереба; «модель» — її розклад, коли її власна λ
  була найбільшою (при малій λ частки — шум, тому не в момент тривоги).
- **Легенда** вердиктів (клік ховає/показує): Спіймано, Запізно, Пропущено, Хибна тривога, Тихий,
  Виключено (спонтанний зрив або контакт зі стінкою).
- **Рядки розрядів**: заливка — бігучий максимум p; пунктир — поріг; червона риска — гасіння;
  кольорова — тривога; далі випередження, **причина за моделлю** (кольоровий стовпчик часток +
  назва), **насправді** (✓ збіг / ✗ ні) і сценарій збурення.
- **Дані прогону**: `measured.csv` (100 каналів + p моделі + її λ і частки на кожному кроці),
  `shots.csv` (мітки, тривога, вердикт), `run.json` (повний звіт; відкривається кнопкою
  «відкрити збережений run.json» і тут, і в toksym).
- **↻ Перерахувати з цими полями** — змінити lead/бюджет і перерахувати звіт без нового прогону.

## 5. 🎛 Керування розрядом

Панель праворуч, працює **під час** розряду. Порядок роботи:

1. **Прогноз зриву** — звідки брати ризик:
   - **Рушій (оракул λ)** — справжня λ симулятора: ідеальний прогноз, щоб налаштувати політику
     керування без жодної моделі;
   - **Ваша модель** — оберіть здачу (найкраще `impactnet` або `v8_impact`), **▶ Під'єднати модель**
     *до* натискання Start. Модель отримує ті самі 100 каналів, що на заліку, на кожному кроці.
   Велике число — p (рушій: імовірність зриву за 1 с; модель: її миттєве p), під ним λ, праворуч графік p.
2. **Чинники зриву зараз** — частки 5 механізмів (Грінвальд, q95, радіація, Тройон, інші).
   Якщо λ < 0.02 — підпис «ризику майже немає»: тоді частки нічого не означають.
3. **Порадник** — головна загроза і конкретна рекомендація («знизити уставку густини до 0.62 і
   D₂ удвічі»). Головна загроза береться з часток моделі, а коли λ мала — з найближчої
   операційної межі за станом плазми (підпис у дужках: «за моделлю» / «за рушієм» / «найближча межа»).
   **Застосувати зараз** — виконати рекомендацію вручну.
4. **Автокерування** (галочка) — рекомендація виконується сама, коли p > **Поріг p**, не частіше
   ніж раз на **Паузу між діями** (плазмі треба час: густина реагує за ~0.3 с, домішки — за ~0.5 с).
   **Мін. λ для часток** — нижче цієї λ частки ігноруються. Кожна дія пишеться в журнал унизу.
5. **Уставки вручну** — 10 повзунків. Помаранчевий — уставка змінена (вами чи автокеруванням),
   ✕ — повернути запрограмовану хвилю, **↺ повернути програму** — скинути все.
   Під повзунками — поточні f_GW, q95, P_rad/P_in, βN.

Таблиця «механізм → дія» показана в панелі; змінити політику можна у функції `advise()` файла
`web/src/components/ControlPanel.tsx` (далі `./build.sh` або `cd web && npx vite build`).

⚠️ Якщо автокерування знижує Iₚ більш ніж на 10 %, моделі v8 / ImpactNet приймають це за
програмований спад струму і віддають p = 0 (детальніше — PHYSICS_CONTROLS.md, розд. 5).

**Типовий сценарій перевірки моделі:** JET → H-mode → Керування → Ваша модель `v8_impact` →
Під'єднати → поставити галочку Автокерування, поріг 0.3 → Start → у ✎ Edit можна заздалегідь
додати збурення (напр. підняти густину) і подивитися, чи модель його помітить і що порадить.

## 6. Як модель віддає причини зриву (для авторів моделей)

Протокол той самий, що в toksym, з одним сумісним розширенням. Сервер у привітанні шле
`"rich": true`, а обгортка `toksym_model.py` ставить `model.rich_answers = True`. Тоді `predict`
може повернути словник замість числа:

```python
def predict(self, t, channels):
    o = self.impact.step(channels)
    p = ...                                   # імовірність для тривоги, 0…1 (обов'язково)
    if not self.rich_answers:                 # toksym: лише число
        return p
    return {"p": p,
            "p_now": p_instant,               # необов'язково: миттєве p для керування
            "risk_total": o["risk_total"],    # λ моделі, 1/с
            "share_pct": o["share_pct"]}      # {'greenwald':…, 'q95':…, 'radiation':…, 'troyon':…, 'other':…}, сума 100
```

Готові здачі в `../models`:

| тека | p (тривога) | причини |
|---|---|---|
| `submission_v8` | v8 (бігучий максимум) | — |
| `impactnet` | 1 − e^(−λ·1 с), 0 на спаді струму | ImpactNet |
| `v8_impact` | v8; `p_now` — EMA v8 без максимуму | ImpactNet |

ImpactNet як будильник слабка (див. її README), тож для тривоги беріть `v8_impact`. Перевірка на
30 розрядах (seed 3): головний механізм вгадано в 5 з 6 зривів.

## 7. Без браузера

```bash
fusionsim gen --shots 200 --seed 1 --out mydata --extras risk,physics      # датасет з мітками λ
fusionsim score --submission ../models/v8_impact --shots 200 --seed 1 \
                --lead 0.1 --budget 0.05 --report run.json --save-data rundata
fusionsim rescore run.json --lead 0.3
python3 tools/closed_loop.py --model ../models/submission_v8 --shots 40 --seed 3 --threshold 0.25
```

`tools/fusion_sim_client.py` — покрокове керування рушієм з Python (див. [../SIM_API.md](../SIM_API.md)).
